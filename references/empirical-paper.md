# Empirical-paper reading guide

Use this guide for quantitative, experimental, observational, and ordinary mixed-method psychology studies. Adapt headings when the paper uses a different structure; do not force absent sections.

## Chunk 1 — Content Analysis

### Introduction: reconstruct the argument

- Summarize each meaningful paragraph or argument unit in a short sentence, retaining its source locator.
- Connect those units as a logical chain: background -> theory or mechanism -> existing evidence -> gap or contradiction -> research purpose -> hypotheses/questions.
- Name theories, constructs, brain regions, and components with Chinese term plus English full name and abbreviation on first appearance when the paper gives them.
- Distinguish an author-stated hypothesis from a reviewer-style inference about the hypothesis.

### Method: explain design before technique

- Report only available details: design, participants/sample, materials or stimuli, procedure, measures, conditions, exclusions, preregistration, and analysis plan.
- For each complex method, model, or computational/AI technique, explain: what it estimates or tests; why the authors used it; which research question it answers; and any stated advantage over alternatives. Tie these to the introduction only when the connection is explicit or clearly marked as interpretation.
- Do not label an analysis "advanced" merely because it has a technical name. If asked, offer a plain-language explanation and a small hypothetical example, separate from the paper's actual data.

### Results: map evidence to questions

- Organize results by research question or hypothesis, then identify the reported statistical test/model, analysis sample size, key statistics, direction, uncertainty, and author conclusion when available.
- Do not equate non-significance with proof of no effect, or statistical significance with practical importance.
- Internally inventory every readable table, figure, and available supplement before writing. Do not display the inventory by default.
- For each readable table or figure, internally record: `Identifier -> research question -> what is displayed -> axes/columns, groups, units, legend, and error/statistical markers when readable -> key visible data or pattern -> related hypothesis -> cautious takeaway -> source locator`.
- Explain the visuals that materially support the user's requested result interpretation in natural prose or a compact table. State that further figure/table explanation is available on request.
- Keep visual interpretation separate from the authors' narrative. If the table/figure and narrative disagree, report the discrepancy and do not choose a version without explaining the evidence.
- If a visual is not readable, do not guess. Request a high-resolution image, source page, or accessible table export.

### Internal result-data audit: verify before summarizing

For every central result claim, create an internal audit record containing: `hypothesis/question -> outcome and coding direction -> model/test -> analysis N -> effect estimate -> uncertainty statistic -> p value or equivalent -> source locator`.

- Compare the result paragraph with the corresponding table/figure, abstract, and discussion claim when each is available.
- Verify that the reported direction agrees with the scale coding. Do not infer whether a higher score is better or worse from the variable name alone.
- Keep the full recruitment sample, wave-specific samples, exclusions, missing-data samples, and model-specific N distinct.
- Verify that a table/figure number, condition label, coefficient sign, confidence interval, and p value refer to the same model and outcome.
- If a value is unavailable, ambiguous, internally inconsistent, or visually unreadable, mark it `Needs user verification`; never repair, average, or select values by assumption.
- Keep the audit status internal by default. Mention it to the user only when a material discrepancy, unreadable source, or unresolved ambiguity affects the conclusion.

### Discussion: reconstruct the response loop

- Trace how the authors connect findings back to each hypothesis or question.
- Separate author claims about consistency with prior work, explanations for consistency/inconsistency, implications, limitations, and future directions.
- Note qualification language such as may, suggest, or consistent with when it limits the claim.

## Chunk 2 — Academic Language

- Select phrases that are genuinely useful and supported by the paper: framing a gap, stating a hypothesis, describing a method, reporting a result, qualifying an inference, and discussing implications.
- For each pattern provide: its communicative purpose, a short source-derived pattern (not a long quotation), a reusable template with slots, a Chinese explanation, and a cautious example unrelated to the paper's unreported data.
- Add a bilingual glossary only for terms actually present or necessary for understanding the selected phrases.

## Quality checks

- Confirm internally that every central summary claim has an audit record and source locator.
- Check sample sizes, scale coding, condition labels, test names, effect directions, coefficients, confidence intervals, p values, and table/figure references against the source before finalizing.
- Confirm internally that each visible table and figure has either been interpreted with the required template or explicitly marked unreadable/unavailable.
- Flag inconsistent values or ambiguous reporting for user verification; do not repair them from assumption.
